# 03 · 經濟與抽獎

> 涵蓋：`js/state.js › castCost() / bonus() / rarityTable() / rollCatch() / recordCatch()`、`js/data.js › FG.RARITY`
> 相關：[10 平衡調參](10-balance-tuning.md)（要改數值看那頁）、[07 資料規格](07-data-schema.md)

這是整個遊戲的心臟。**改這裡之前先讀完整頁**，公式之間有耦合。

## 籌碼流向全圖

```
流入                                    流出
─────────────────────────────────       ─────────────────────────────
賣魚          sell()                    拋竿      castCost()
每日簽到      claimSignin()             餌料      buyBait()
每日任務      claimMission()            釣竿      buyRod()
籌碼包        buyPack()（測試版直給）    裝備      buyEquip()
                                        魚缸擴建   upgradeTank()
                                        家園裝飾   buyDeco()
```

> **釣點解鎖已經不是流出項。** 四個釣點都改成免費切換（[07 §為什麼四個釣點都是免費的](07-data-schema.md#為什麼四個釣點都是免費的)），`unlockLoc()` 現在跑不到。籌碼的消耗池只剩「拋竿費＋餌料」這條主線，以及釣竿／裝備／魚缸／裝飾這些一次性升級。

**主要循環是「拋竿 → 賣魚」**，其他都是輔助。設計目標：拋竿的期望回報略高於成本（新手約 ×1.2），讓玩家穩定前進但不會爆富；花錢升級裝備能把倍率推到 ×2 左右，同時大幅提高魚王機率——**吸引力來自魚王與圖鑑，不是來自倍率**。

## 稀有度階級

定義在 `data.js › FG.RARITY`，順序在 `FG.RARITY_ORDER`：

| key | 名稱 | 基礎權重 | order | 顏色 |
|---|---|---|---|---|
| `junk` | 雜物 | 90 | 0 | `#8b8f96` |
| `common` | 普通 | 520 | 1 | `#c8d3dd` |
| `good` | 優良 | 260 | 2 | `#5fd08a` |
| `rare` | 稀有 | 90 | 3 | `#59a6ff` |
| `epic` | 史詩 | 30 | 4 | `#b775ff` |
| `legend` | 傳說 | 8 | 5 | `#ffc44d` |
| `king` | 魚王 | 2 | 6 | `#ff5f6d` |

權重總和刻意湊成 **1000**，方便心算成千分比。`order` 用來做「≥ 某稀有度」的比較（自動模式的停止門檻、稀有以上收藏都靠它）。

## 加成來源

| 來源 | 提供什麼 | 進入路徑 |
|---|---|---|
| 釣竿 | `rareMul` `sizeBonus` `kingMul` | `bonus()` |
| 裝備 | `rareMul` `valueMul` `costMul` `sizeBonus` `showHint` | `bonus()` |
| 家園裝飾 | `rareMul` `valueMul` | `bonus()` |
| **餌料** | `rareMul` `junkMul` `valueMul` `kingMul` | **不經過 `bonus()`**，在 `rarityTable()` / `rollCatch()` 直接讀 `state.bait()` |

同類加成**相乘**（不是相加）。餌料獨立於 `bonus()` 是刻意的：餌料是消耗品、可隨時切換，其他是持久狀態。但這造成一個常見錯誤——算實際稀有度倍率必須寫 `bonus().rareMul * bait().rareMul`。

## 拋竿成本

```js
castCost(loc) = round(loc.castCost * bonus().costMul)
```

只有「防水背心」提供 `costMul: 0.85`。**餌料成本不含在裡面**，是另外扣一份庫存（買的時候就付過錢了）。所以一次拋竿的真實成本 = `castCost()` + 該份餌料的單價。

## 稀有度權重表 · `rarityTable(loc)`

這是抽獎的核心，也直接餵給 UI 的「中獎機率」費率表（所以玩家看到的機率一定跟實際一致，不會有兩份邏輯）。

```js
M = bonus().rareMul * bait().rareMul     // 稀有度總加權
K = bonus().kingMul * bait().kingMul     // 魚王專屬加權

for 每個「該釣點實際有魚的」稀有度:
  w = RARITY[key].weight
  junk    : w *= bait().junkMul
  common  : 不變
  good    : 不變
  rare    : w *= M
  epic    : w *= M^0.85      ← 遞減
  legend  : w *= M^0.70      ← 遞減更多
  king    : w *= K           ← 只吃 K，完全不吃 M
```

### 為什麼是這個形狀（重要設計決策）

初版是「rare 以上全部乘 M，king 再額外乘 K」。實測滿裝配置下**魚王機率飆到 6.8%**，因為 M 和 K 都是多個 1.2～2.5 的倍率連乘，疊起來變成 70 倍。魚王一旦變成常態，整個追逐感就沒了，籌碼也會失控。

修正成上面的形狀：
- **指數遞減**（`^0.85` / `^0.70`）讓高階稀有度對裝備的敏感度逐級下降。
- **魚王完全脫離 M**，只由 `kingMul` 控制。這樣「想拚魚王」就必須明確地選龍骨竿＋魚王秘餌，而不是靠堆一般稀有度加成順便刷出來。

結果：魚王機率從新手 0.20% 到滿裝 0.93%，成長 4.6 倍，感覺得到但不失控。

### 其他要點

- **只有該釣點實際存在的稀有度才會進表**。所以新釣點如果沒放史詩魚，那 30 點權重就不存在，其他階級的相對機率會自動變高。加魚時要意識到這件事。
- 權重歸一化在最後才做（`r.pct = r.weight / total`），所以任何一階被拉高，其他階都會被稀釋。
- `bait_king` 的 `junkMul = 0` 會讓雜物權重歸零，雜物直接從表上消失。

## 抽一次漁獲 · `rollCatch(loc)`

```
1. rows = rarityTable(loc)
2. row  = weightedPick(rows, r => r.weight)          ← 先抽階級
3. fish = pick(row.fish)                             ← 階級內「等機率」抽魚種
4. 體型
     t = skewed(2.4)                                 ← pow(random, 2.4)，偏小
     t = clamp(t * (1 + sizeBonus) + sizeBonus*0.25, 0, 1)
     len = minLen + (maxLen - minLen) * t
5. 重量
     weight = len^3 * density[shape]                 ← 立方律，density 依體型
6. 閃光
     shiny = 非雜物 && random < 0.03
7. 價值
     value = fish.value * (len / avgLen)^2.0
     非雜物 → *= bonus().valueMul * bait().valueMul
     shiny  → *= 3
```

### 各段的設計理由

**階級內等機率**：同一階級的魚不分軒輊，靠 `value` 和體長範圍拉開差異。想讓某條魚更罕見，把它升一階，不要在階級內做二次權重——那會讓費率表失真。

**`skewed(2.4)`**：`pow(random, 2.4)` 的分布重心在 0.29 左右，意思是**大部分魚偏小**，釣到接近上限的大物是稀有事件。這讓「同一種魚」也有收集價值（刷最大體長紀錄）。

**`sizeBonus` 的兩段式**：`t * (1+bonus) + bonus*0.25`。乘法讓整條分布拉伸，加法給一個保底抬升，避免小魚永遠是小魚。滿裝 `sizeBonus = 0.43`（龍骨竿 0.35 + 大型魚簍 0.08）。

**重量的 density 表**（`rollCatch()` 內）：
```
normal 2.0e-5 | long 6.0e-6 | round 2.8e-5 | flat 2.4e-5 | wide 2.2e-5 | ray 2.0e-5
```
細長體型（`long`）密度低是符合直覺的——同樣 100cm 的鰻魚比鯉魚輕得多。**重量純粹是展示用，不參與任何計算。**

**價值的平方律**：`(len/avg)^2`。體長翻倍價值變 4 倍。用平方而不是立方（雖然重量是立方）是為了不讓大物價值誇張到破壞經濟。

**閃光 3%**：固定值，不受任何裝備影響。是純粹的驚喜事件，價值 ×3。

## 寫入紀錄 · `recordCatch(inst)`

```
圖鑑 codex[fishId] → 有就 n++ 並更新 maxLen；沒有就建立
stats.caught++、魚王另計 stats.kings++
每日任務：casts +1；稀有以上 → rares +1；isNew → newCodex +1
emit('codex')
```

> **`recordCatch()` 和「賣出／收藏」是分開的兩件事。** 圖鑑在釣到的當下就記錄，之後不管賣掉、收藏還是放生都不影響。這是為了讓玩家能安心賣魚。
>
> ⚠️ 手動流程在 `showResult()` 裡呼叫 `recordCatch()`；自動流程在 `resolveAuto()` 裡呼叫。**「魚缸滿了轉交手動」這條路徑會走 `showResult()`，所以 `resolveAuto()` 在那個分支必須跳過 `recordCatch()`，否則會記兩次。** 現行程式碼是靠 early return 處理的，改動時務必保持。

## 目前的平衡數據

以模擬 30 萬次拋竿估算（腳本與完整表格見 [10 平衡調參](10-balance-tuning.md)）：

| 配置 | 產出/成本 | 魚王 | 傳說 | 史詩 | 稀有 |
|---|---|---|---|---|---|
| 竹竿＋麵包屑（新手） | ×1.20 | 0.19% | 0.80% | 3.00% | 8.99% |
| 碳纖竿＋活蝦＋帽/簍 | ×1.77 | 0.28% | 1.20% | 5.00% | 16.59% |
| 秘銀竿＋假餌＋4 裝備 | ×2.02 | 0.35% | 1.50% | 6.78% | 24.24% |
| 龍骨竿＋魚王秘餌＋全裝備 | ×1.89 | 0.85% | 1.73% | 8.30% | 31.48% |
| 同上，落霞峽灣 | ×2.29 | 0.93% | 1.76% | 8.29% | 31.24% |
| 同上，幽藍冰湖 | ×2.40 | 0.89% | 1.70% | 8.28% | 31.36% |
| 同上，深淵海溝 | ×2.49 | 0.86% | 1.72% | 8.30% | 31.46% |

**滿裝倍率略低於後期是刻意的**：魚王秘餌單價 900，貴到把倍率吃掉一部分。玩家用它是為了魚王機率翻倍，不是為了賺錢。這是「高風險高變異」的博弈選項。

**注意各階級機率跟釣點無關**：權重表只看「該釣點有哪些階級有魚」，而四個釣點每一階都有魚，所以四張費率表完全一樣。釣點之間的差別純粹在**絕對值**（深淵一竿的 EV 是晨霧湖的 12 倍）與魚種內容。

**釣點越深滿裝倍率越高**（1.89 → 2.29 → 2.40 → 2.49）是餌料成本佔比造成的副作用，被刻意保留成進程獎勵，理由見 [10 §為什麼後段釣點的滿裝倍率比較高](10-balance-tuning.md#為什麼後段釣點的滿裝倍率比較高)。
