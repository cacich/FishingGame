# 04 · 釣魚循環

> 涵蓋：`js/screen-fishing.js`、`js/cutin.js`（自動模式的部分另見 [05](05-auto-mode.md)）
> 相關：[03 經濟](03-economy.md)、[06 像素引擎](06-pixel-engine.md)

## 狀態機

```
        ┌──────────────────────── idle ◄───────────────────┐
        │                          │                       │
   拋竿按鈕 / 自動排程              │ cast()                │
        │                          ▼                       │
        │                    ┌──────────┐                  │
        │                    │   cast   │ 浮標飛出（拋物線）  │
        │                    └────┬─────┘                  │
        │                         ▼                        │
        │                    ┌──────────┐                  │
        │                    │   wait   │ 浮標微沉浮        │
        │                    └────┬─────┘  聲納在 55% 處提示 │
        │                         ▼                        │
        │                    ┌──────────┐                  │
        │                    │   bite   │ 浮標下沉＋漣漪     │
        │                    └────┬─────┘                  │
        │                         │                        │
        │              傳說以上？ ─┤                        │
        │                    ┌────▼─────┐                  │
        │                    │  cutin   │ 登場演出（可跳過:否）│
        │                    └────┬─────┘                  │
        │                         ▼                        │
        │                    ┌──────────┐                  │
        │                    │   reel   │ 魚躍出水面        │
        │                    └────┬─────┘                  │
        │                         ▼                        │
        └──── showResult() 或 resolveAuto() ────────────────┘
```

狀態存在 `S.phase`（字串），階段起始時間存 `S.t0`（rAF 時間戳）。轉場條件全部在 `frame()` 裡用 `now - t0` 判斷。

`cutin` 是**條件性階段**：只有 `S.cutinPlan` 不是 `null` 時才會插進來，否則 `bite` 直接接 `reel`。

## 時間軸

各階段長度在 **`cast()` 當下**算好存進 `S.dur`，之後整段演出不再變動（即使中途改速度也不會走位）：

| 階段 | 手動 | 自動 | 說明 |
|---|---|---|---|
| `cast` | 700 ms | 700 / spd | 浮標從船邊飛到落點 |
| `wait` | 1200 + rand×2200 | (500 + rand×800) / spd | 隨機等待，自動模式縮短 |
| `bite` | 850 ms | 850 / spd | 浮標下沉 |
| `cutin` | 傳說 1250／魚王 2100 | **同左，不除以 spd** | 只有傳說以上才有這一段 |
| `reel` | 1100 ms | 1100 / spd | 魚躍出水面 |

`spd` 來自 `S.spd()`：手動固定 1，自動時取 `auto.speed`（1／2／4）。
手動總長約 3.9～6.1 秒（傳說 +1.25 秒、魚王 +2.1 秒）；自動極速（spd=4）約 0.9 秒＋0.08 秒間隔。

### 為什麼 `cutin` 不跟著加速

其他階段除以 `spd` 是為了讓自動模式能快速跑量，但 cut-in 的存在理由正好相反——它是「值得停下來看」的東西。極速模式把它壓成 0.5 秒，玩家只會看到一團閃光，等於白做。而且傳說以上的基礎機率只有 1%（`FG.RARITY` 的 weight 8＋2 ÷ 1000），跑 500 局大約遇到五次，多花的十秒不影響掛機效率。

## 場景座標

場景 canvas 是固定的 **200×340**（`FG.px.sceneSize`），CSS 用 `object-fit: cover` 撐滿容器。所有座標都是這個空間裡的：

```js
const FLOAT_HOME = { x: 112, y: 232 };   // 船邊，收線後浮標停這
const FLOAT_CAST = { x: 152, y: 208 };   // 落點
```

`cast` 階段用 `lerp` 從 HOME 移到 CAST，再減去 `sin(t·π) × 34` 做出拋物線弧度。

## 每幀送給場景的狀態

`frame()` 組出一個 `sceneSt` 交給 `FG.px.drawScene(ctx, loc, sceneSt)`：

```js
{
  time:      now,        // 驅動水面反光、船／釣手／狗待機序列與愛心
  floatX/Y:  數值,        // 浮標位置
  floatSink: 0..1,       // 浮標沉入程度（bite 階段 0→1）
  ripple:    bool,       // 是否畫漣漪（bite / reel）
  hideLine:  bool,       // 是否隱藏釣線與浮標（目前未使用）
  jump:      { fish, t } // 躍出水面的魚與進度 0..1（reel 階段）
}
```

繪製細節見 [06 像素引擎 §場景](06-pixel-engine.md#三--釣點場景)。

### 船上角色的待機動畫

`sceneSt` 不需要新增 `phase`：目前 `assets/characters/fishing-idle.png` 是十二格、每格 112×64、每 100ms 換格的**通用待機循環**，在 `idle`、拋竿、等待、咬鉤與收線期間都持續播放；各階段真正會變的釣竿、釣線、浮標與躍魚仍由 `drawScene()` 逐幀繪製。角色改採低船身、坐姿小釣手與船首狗，尺寸接近舊程序化船，不再搶過場景。十二格不是逐格重新產圖，而是由同一組船／人／狗母版分層組合，只做 1px 的船身浮動、呼吸與狗狗微動；這樣增加流暢度時不會讓輪廓在格與格之間變形。

序列每格另有握竿錨點與船身位移（`pixel.js › FISHING_IDLE.rodAnchor`／`boatOffsetY`）。人物呼吸與船身上下移 1px 時，釣竿起點和倒影必須跟著該格資料，否則會出現「人物在動、竿子浮在手旁邊」或倒影反向抖動。後續若新增拋竿／收線序列，也要為每一格提供同樣的錨點。

## 拋竿前置檢查 · `canCast()`

回傳 `{ ok, why, msg }`，`why` 是 `'bait'` 或 `'chips'`。

**這個函式同時服務手動與自動兩條路**：
- 手動：`cast()` 收到失敗會跳彈窗，並提供導向按鈕（去商店 / 開儲值）。
- 自動：`cast(true)` 收到失敗**先試著補餌**（`why === 'bait'` 時呼叫 `autoRestockBait()`，成功就遞迴重拋一次），補不到才呼叫 `stopAuto(chk.msg)`，全程不跳彈窗。

  這一層是修過的 bug：少了它，在餌料歸零時按「開始自動」會直接停在 0 局，玩家設定的「自動補貨」形同無效。細節見 [05 §餌料補貨](05-auto-mode.md#餌料補貨--autorestockbait)。

改停止條件時記得兩邊都會受影響。

## 扣款與抽獎的順序

```js
st.pay(cost);            // 1. 先扣籌碼
st.useBait();            // 2. 扣一份餌料
st.data.stats.casts++;   // 3. 計數
this.pending = st.rollCatch(loc);   // 4. 抽獎，結果存起來
this.cutinPlan = FG.cutin.plan(...) // 5. 決定要不要插 cut-in
this.phase = 'cast';                // 6. 開始播演出
```

**結果先抽好、演出只是播放**，這個設計帶來四個好處：
1. 聲納裝備可以在 `wait` 階段提前顯示稀有度（`showHint`）。
2. **cut-in 可以在 `bite` 結束時就知道要不要插、要插哪一套**，不需要另外查一次。
3. 自動模式可以任意加速甚至理論上跳過演出，不影響結果。
4. 不會有「演出播到一半才發現扣款失敗」的狀態不一致。

`S.pending` 在結算後清成 `null`。**它是唯一橫跨多幀的暫存狀態**，改動時注意所有分支都要正確清掉（尤其自動模式「魚缸滿轉手動」那條路是刻意**不清**的，因為要交給 `showResult()` 用）。

`S.cutinPlan` 也橫跨多幀，但規則不同：**它只由 `cast()` 覆寫，任何地方都不該把它清成 `null`**。理由見下方 §疊層的生命週期。

## 跳過演出 · `skip()`

點畫面任意處會把 `t0` 往前推，讓當前階段立刻結束。**只在手動模式生效**（自動模式 early return），避免玩家亂點打亂自動節奏。只有 `cast` 和 `wait` 可以跳；`bite` / `cutin` / `reel` 是演出高潮不給跳。

`cutin` 不需要另外寫排除邏輯——`skip()` 是白名單（只認 `cast` 和 `wait`），新增階段預設就是不可跳。

## 聲納提示

裝備「聲納探測器」提供 `showHint: true`。在 `wait` 階段跑到 55% 時，把提示顯示在畫面中央。**文字分兩種**：

| 抽到的稀有度 | 顯示 |
|---|---|
| 雜物～史詩 | `聲納：偵測到「史詩」等級魚影` |
| **傳說、魚王** | `聲納：強　烈　訊　號` |

傳說以上刻意**只報訊號強度、不報等級**。後面有 cut-in 負責揭曉，這裡先講出「傳說」等於把驚喜先用掉，聲納會從「值得買的裝備」變成「劇透器」。判斷用 `R.order >= FG.RARITY.legend.order`，跟 cut-in 的門檻是同一個條件，將來調門檻要兩邊一起改。

用 `S.hinted` 旗標確保每次拋竿只提示一次。

## cut-in · 傳說以上的登場演出

實作在獨立的 `js/cutin.js`（`FG.cutin`），screen-fishing 只負責在對的時機呼叫。

### 為什麼獨立成一個檔案

`screen-fishing.js` 本來就 640 行，塞進去會變成一千多行，而 cut-in 跟釣魚流程其實沒有耦合——它不讀狀態、不改狀態、不決定結果，只是拿一條魚把畫面演完。分開之後改演出不用碰狀態機，改狀態機也不用讀四百行動畫碼。

### 對外的三個函式

| 函式 | 做什麼 |
|---|---|
| `plan(fish)` | 回傳 `{ kind, dur, scale, motif, particle, title, tone }`，不需要 cut-in 時回 `null`。門檻是 `R.order >= FG.RARITY.legend.order` |
| `play(mount, fish, inst, plan)` | 建疊層、跑動畫、播音效。`mount` 要是 `position: relative` 的容器（釣魚畫面傳 `#stageWrap`） |
| `clear(mount)` | 拆疊層 ＋ 取消還沒響的音效 timeout。**可重複呼叫** |

screen-fishing 這一側對應 `startCutin()` / `clearCutin()` 兩個薄包裝。

### 兩種強度

| | 觸發 | 長度 | 演出 |
|---|---|---|---|
| 傳說 | `rarity === 'legend'` | 1250 ms | 金色斜切光帶掃過 ＋ 魚影從左滑入 ＋「傳　說」 |
| 魚王 | `rarity === 'king'` | 2100 ms | 壓黑到 86% ＋ 畫面震動 ＋ 放射線 ＋ **每位魚王專屬的骨架與配色** |

### 每位魚王都不一樣，但不是各刻一套

二十位魚王共用**四種演出骨架（motif）**，各自配一筆參數。這是刻意的取捨：

- 各刻一套要 700～1000 行，而且[加一個釣點就要生一整套內容與正式美術](09-recipes.md#新增一個釣點--一次要生出一整套)，cut-in 會成為其中最花時間的一項。
- 參數化之後新的魚王只要在 `cutin.js › KING` 補一筆六行的資料。

差異感從四個地方來，加起來足夠讓二十位看起來是二十場不同的演出：

| 差異來源 | 從哪來 |
|---|---|
| 進場方式 | `motif`（四選一） |
| 主色調 | **魚自己的 `colors.glow` / `colors.pattern`**，不另外設定 |
| 粒子動線 | `particle`（三選一），顏色同樣吃魚的配色 |
| 登場音階 | `tone` 陣列，交給 `FG.sfx.seq()` |

四種骨架：

| motif | 演出 | 適合 |
|---|---|---|
| `emerge` | 從下方緩緩浮起放大 | 沉在水底的巨物 |
| `charge` | 從左側高速衝入，帶兩層殘影 | 有速度感的掠食者 |
| `spiral` | 縮到極小旋轉著放大，外圈符文環反向旋轉 | 神格化的存在 |
| `reveal` | 上下黑幕合攏後拉開，像布幕 | 藏在黑暗／沙塵裡的東西 |

> **但「補最少的那一種」不能凌駕於「合不合這條魚」。** 2026-08-05 加的三位魚王沒有一位配 `charge`（從左側高速衝入），因為三位剛好都是**不動的東西**：伏石趴在石頭上二十年、琉璃每天慢慢游回同一個洞、長息四十分鐘才呼吸一次。硬塞一個衝刺演出給牠們，玩家看到的是演出跟這條魚的傳說對不上——那比骨架分佈不平均糟得多。`motif` 相同的兩位仍然靠**魚自己的配色**（`colors.glow` 是 cut-in 主色）與 `particle`／`tone` 區分，所以同一種給到第四位還撐得住。

**新增魚王忘了補 `KING` 表不會報錯**，會退化成 `KING_FALLBACK`（emerge ＋「魚　王」）。刻意這樣——少一筆資料不該讓玩家釣到魚王卻看到當機。代價是漏了不會被發現，所以[加釣點的清單](09-recipes.md#新增一個釣點--一次要生出一整套)裡列了這一項。

### 為什麼是 DOM 疊層不是畫進 canvas

場景 canvas 用 `object-fit: cover`（[11 §10](11-invariants-and-gotchas.md#10-場景-canvas-是-object-fit-cover)），畫上去的東西邊緣會被裁掉、位置也不可控。疊層做成 DOM 就沒這問題，還能直接用 CSS keyframes 做斜切、震動、粒子。魚本身仍然是 `FG.px.spriteEl()` 的快取精靈，**整個功能沒有新增任何圖檔**。

疊層 append 進 `#stageWrap`，是 `#stage`（canvas）與 `#stageHud` 的兄弟節點，不進 `#stageHud`——那裡是 `flex-direction: column` 的版面流，塞一個滿版元素進去會把 banner 和 castMsg 擠掉。

### 疊層的生命週期

正常路徑是 `bite` 結束時 `play()`、`cutin` 結束時 `clear()`。麻煩的是**分頁切走時 `frame()` 不再被呼叫**（[01 §主迴圈](01-architecture.md#主迴圈)），疊層會留在 DOM 裡。兩道防線：

1. **所有 CSS 動畫的收尾都淡出到 `opacity: 0`**（`.cutin-legend` / `.cutin-king` 的 `ciOut`）。就算沒被即時移除，留在 DOM 裡的也是看不見的。
2. `onShow()` 在 `phase !== 'cutin'` 時呼叫 `clearCutin()` 補一刀。

> ⚠️ `clearCutin()` **只拆疊層，不碰 `S.cutinPlan`**。玩家很可能在 `wait` 階段切走再切回來，那時 plan 已經決定好、還沒輪到播；在這裡順手清掉 plan 會讓那一竿的 cut-in 整個消失。plan 由 `cast()` 每次覆寫，不需要別人幫忙清。

### 時間軸是跨檔案綁死的

`cutin.js` 的 `DUR_LEGEND` / `DUR_KING` 決定 phase 停多久，`styles.css` 的 keyframes 決定畫面演多久。**兩邊必須對齊**：JS 比 CSS 短會「動畫沒演完就跳去收線」，長會「演完了畫面卡著等」。已寫進 [11 §26](11-invariants-and-gotchas.md)。

## 結果卡 · `showResult()`

手動模式的結算。組出 `.catch-card` 放進 `FG.ui.modal`：

- **稀有度色帶**：背景 `色碼 + '22'`（13% 透明度）、文字用該稀有度顏色。閃光個體前面加 `✦ 閃光 ✦`。
- **魚的大圖**：`FG.px.spriteEl(fish, 3)`（3 倍放大）。閃光個體額外套 CSS filter 提高飽和度＋光暈。
- **NEW 徽章**：`inst.isNew` 時掛在魚名後面。
- **個人新紀錄**：`isRecord && !isNew` 才顯示（新魚必然是紀錄，沒必要重複講）。
- **傳說文字**：`fish.legend` 存在就用 `.legend` 樣式（琥珀色框），否則顯示 `fish.desc`。
- **兩個按鈕**：「收藏展示」（`close: false`，失敗時不關閉彈窗只跳 toast）、「賣出 +N」。

彈窗設成 `dismissable: false`，**必須做出選擇才能關**，避免玩家點外面就把魚弄丟。

|---|---|
| `baitPicker()` | 餌料快速切換。有庫存顯示「選用」，沒庫存顯示「購買」並導向商店 |
| `rateModal()` | 中獎機率費率表。**直接讀 `rarityTable()`**，跟實際抽獎共用同一份計算，不會有兩份邏輯不同步的問題 |

## 訂閱的事件

`build()` 裡訂了三個：

```js
FG.state.on('gear',  → refresh());   // 換竿／換餌／買裝備後更新裝備列與成本
FG.state.on('loc',   → 自動模式強制停止 + refresh());
FG.state.on('codex', → refresh());   // 更新標題列的圖鑑進度
```

**切換釣點會強制中止自動模式**，因為費率、成本、魚種全變了，繼續跑會讓結算數字沒有意義。
