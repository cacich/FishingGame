# 14 · 開發者面板

> 涵蓋：`js/devtools.js`
> 相關：[03 經濟與抽獎](03-economy.md)、[04 釣魚循環](04-fishing-loop.md)、[08 介面](08-ui-and-screens.md)

測試用的隱藏面板。要驗一個只在魚王身上發生的問題時，不用坐在那裡拋兩千竿。

## 怎麼打開

**快速連點底部「家園」分頁鈕 10 下**，每兩下之間不能超過 600ms。點到第 6 下開始會跳 toast 提示還差幾下。

連點的同時分頁照常切到家園（沒有 `preventDefault`），所以誤觸的人只會覺得「我按了很多次家園」。

參數在 `devtools.js` 開頭：`TAP_NEED` / `TAP_GAP`。

### 為什麼是連點而不是按鈕或網址參數

- **按鈕**會被玩家看到，得另外做「確定要進入開發者模式嗎」，變成要維護的 UI。
- **網址參數**（`?debug=1`）在手機上要打字，而這個遊戲是手機直式的，實際測試多半在手機或手機模擬尺寸下進行。
- **連點**手機桌機都按得出來，也不需要鍵盤。

## 面板裡有什麼

| 區塊 | 項目 | 說明 |
|---|---|---|
| 抽獎控制 | 必出稀有度 | 只列出**當前釣點真的有的階級** |
| | 必出魚種 | 當前釣點的所有魚，依稀有度分組。**與必出稀有度互斥**，選一個另一個會自動歸零 |
| | 必出閃光 | 雜物仍然不會閃光（與 `rollCatch()` 的原始條件一致） |
| 演出 | 立即播放 cut-in | 選任一傳說／魚王直接播，**不用真的釣到、不動存檔**。有普通版與閃光版 |
| 資源 | 籌碼 ±、餌料 +99、魚缸拉到最大 | |
| 圖鑑 | 全部解鎖 / 全部清空 | 清空會跳確認，只動 `data.codex` |
| 目前數值 | `bonus(loc)` 的實際回傳值 | rareMul / kingMul / valueMul / costMul / sizeBonus / showHint，調完裝備直接對答案，不用開 console |

## 兩個設計原則

### 一 · 不污染存檔

**所有開關只活在記憶體裡，重新整理就全部恢復**，一個位元組都不寫進 `data`，也不像 `fg_seen_intro` 那樣另開 localStorage key。

理由：調試狀態能存活到下一次開啟，就代表它有機會被忘記。而「必出魚王」被忘記兩天之後，症狀是「這遊戲機率壞了」——那是最難查的一種 bug，因為沒有人會想到去看三天前開的開關。**跨 session 存活省下的那點方便，遠不值得這個風險。**

代價是重開瀏覽器要重新設一次。這個專案重載很快，可以接受。

「資源」與「圖鑑」那兩區當然會寫進存檔（它們本來就是在改存檔），這裡講的是**干預抽獎的那三個開關**。

### 二 · 不改動遊戲邏輯的原始碼

必出稀有度**不是**在 `state.js › rollCatch()` 裡加 `if (FG.dev...)`。做法是包住 `state.rarityTable()`：

```js
st.rarityTable = function (loc) {
  const rows = realTable.call(this, loc);
  if (dev.forceFishId) return [ 只有那一條魚的單列表 ];
  if (dev.forceRarity) return [ 只有那個階級的單列表 ];
  return rows;
};
```

`rollCatch()` 的流程是「`rarityTable()` 給加權表 → `weightedPick` 選階級 → `FG.pick` 從該階級選一條魚 → 算體長／重量／價值／閃光／圖鑑判定」。**只換掉第一步，後面整段完全沒動**，所以測出來的體長分佈、價值、`isNew` / `isRecord` 全是真的。

實測 30 次必出魚王：體長 150～248.7cm、價值 27,854～116,232 籌碼，還自然出現一次閃光——那正是應該看到的樣子。如果是在 `rollCatch()` 裡硬塞一個假 instance，這些數字全部會是假的，測了等於沒測。

掛勾在**第一次打開面板時**才安裝（`installHooks()`），沒打開過的話 `state` 的方法完全沒被碰過。

> 副作用（刻意保留）：釣魚畫面的「查看費率」在干預時會顯示 100%。因為 `rateModal()` 跟抽獎共用同一個 `rarityTable()`（[04](04-fishing-loop.md#其他彈窗)），這是設計本來就要的一致性。那個 100% 正好是「我現在開著必出」的提醒。

## `#devFlag` · 頂部列正中央的 DEBUG 標記

只要三個干預開關有任何一個是開的，頂部列正中央就會掛一個閃爍的紅色 `DEBUG` 標記，寫著目前開了什麼（例：`DEBUG · 必出 魚王 · 全閃光`）。點它會重新打開面板。

**這不是裝飾。** 沒有它，忘記關掉的成本就是上一節講的那種查不出來的 bug。任何未來新增的「會改變遊戲行為」的開關，都要記得加進 `dev.anyActive()` 與 `refreshFlag()` 的敘述裡。

### 為什麼是「塞進頂部列」而不是「浮在畫面上」

原本它是 `position: fixed; left: 6px; top: 6px`，**正好蓋住頂部列的釣點按鈕 `#topLocBtn`**——開著 DEBUG 就換不了釣點，而測不同釣點的魚王正是這個面板最常見的用途。

改成置中之後，`fixed` 就不夠用了：固定定位只知道視窗中線，不知道左右兩顆按鈕多寬，而**錢包 `#chipsBtn` 的寬度會隨籌碼位數變動**（開發者面板本身就有「+1 億」）。實測 `left: 50%; transform: translateX(-50%)` 在 375px、籌碼只有三位數時就已經壓到錢包 6px，籌碼九位數時更慘。

現在的做法是 `refreshFlag()` **把標記插進 `#topbar` 當一個 flex 項目**，並在它右邊補一個 `.grow`：

```
#topLocBtn | .grow（原本就有） | #devFlag | .grow（refreshFlag 插的） | #chipsBtn
```

前後兩個彈性空白等寬 → 標記自然置中；空間不夠時由 `min-width: 0` ＋ `text-overflow: ellipsis` 讓標記自己縮短，**排版保證它永遠不會壓到任何按鈕**。實測 375px 寬、兩個開關全開（24 個字元）時完整顯示不截斷；320px 會截斷成省略號，完整內容仍在 `title` 裡。

> `#devFlagSpacer` 那個 `.grow` 是 `refreshFlag()` 動態插的，**移除標記時要跟著移除**（否則關掉 DEBUG 之後頂部列會多一個彈性空白，錢包被推到奇怪的位置）。兩件事都在 `refreshFlag()` 的 `!dev.anyActive()` 分支裡。

## 新增一個開關要做什麼

1. 在 `dev` 物件加欄位（**預設值必須是「不干預」**）。
2. 會改變遊戲行為的話，加進 `anyActive()` 與 `refreshFlag()` 的文字。
3. `openPanel()` 裡加 UI。沿用既有語彙：`seg()`（分段選擇）、`row(label, child)`、`note(html)`、`head(text)`。
4. 需要攔截遊戲邏輯的話，**優先考慮包住既有函式**而不是在該函式裡加 `if`。包不了才回頭改原始碼。
5. 更新本頁的表格。

## 對正式版的影響

`devtools.js` 是**會被打包進正式版的**（在 `index.html` 與 `sw.js › ASSETS` 裡）。這是刻意的：

- 它只有 325 行、沒有任何資產，體積可以忽略。
- 拿掉它就得為「開發版／正式版」做兩套建置流程，那會破壞「雙擊 `index.html` 就能跑」這個核心約束（[11 §架構](11-invariants-and-gotchas.md#架構)）。
- 這是一個 demo 專案，玩家找到彩蛋面板不會造成任何損害——沒有伺服器、沒有排行榜、沒有金流，所有數值本來就存在自己的 localStorage 裡，用 console 一行就能改。**防作弊在這裡沒有意義。**

真的要出商業版時，把 `index.html` 的那一行 `<script>` 與 `sw.js › ASSETS` 的那一列拿掉就好，其他檔案完全不需要動——這也是把它做成獨立檔案而不是塞進 `main.js` 的理由。
